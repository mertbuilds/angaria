# 0010. MCP agents may sign, delete and act on any company, behind a switch

Accepted, 2026-10-10. Supersedes the "no signing tool" part of 0009 and its tool list; the rest of 0009 (the server, its access checks, tools in the webview, the bridge) stands.

## Context

0009 kept signing out of MCP: an agent could only draft, and the user signed by SMS in the app. Mert wants everything the app does to be reachable from an agent, signing included: "user should be able to provide sms code to their agent and mcp should be able to approve the invoice". He also wants the tools to work on any of the user's companies, not only the one selected in the sidebar.

GİB signs with an SMS şifresi sent to the account's registered phone. The code is only verified on the session that asked for it (the OID belongs to that session), it expires after about three minutes, and GİB allows one open session per user. A signed invoice is a legal document: it cannot be deleted, only cancelled through a request the buyer answers on the portal.

## Decision

- Everything the user can do in the app is a tool, unless it is impossible or unsafe: invoices (list with status and recipient filters, detail or GİB's page, draft, Tekrar kes as `duplicate_invoice`, the downloads into ~/Downloads, delete a draft), SMS signing, customers and services (list, get, create, update, delete), the companies, the company details the PDF prints, TCMB's rate, the GİB login check and Oturumu kapat, and Faturalardan içe aktar (scan, then apply chosen keys). Left out: the GİB credentials and the Polar license (never readable or writable over MCP), switching the app's active company, theme and palette, the dev emulator switch, and cancelling a signed invoice, which neither the app nor the SDK supports (the portal's cancellation request). `cancel_invoice` is renamed `delete_draft`: it always deleted drafts, and "cancel" means the portal's iptal for signed invoices.
- A second switch on the MCP page, İzinler › Ajanlar onaylayabilir ve silebilir, off by default (`allowActions` in localStorage `angaria-mcp`). Off, agents read, draft and add records as under 0009. On, they may also sign, delete drafts, customers and services, change the company details (the IBAN on every PDF) and close the GİB session. The gated tools stay in tools/list while the switch is off and answer a Turkish error that names the switch, so the agent can tell the user what to do; hiding them would leave the agent guessing, and the Rust server gets the list once at start (no `listChanged`). `MCP_TOOL_COPY` in `src/lib/mcp.ts` marks the gated tools (`gated: true`); the page and the web `/mcp` page show the mark, and a test keeps both in step.
- Signing mirrors the app's flow in two calls. `request_signing_sms` (uuids, at most 20) leases the company's GİB session (`gib.lease`, as `useSMSSign` does), checks that each uuid is an unsigned draft of that company, has GİB send the code (`startSMSSign`) and returns an operation id, the drafts with their recipients and totals, and the phone with all but its last four digits masked. `sign_invoices` (operation id and the code the user typed to their agent) verifies the code on that same session (`verifyAndSign`), reads the statuses back from GİB's list and ends the operation. The code is checked with the app's own copy (`smsCodeError`, `src/lib/sms-code.ts`) and errors come from `GIB_ERROR_COPY` like the dialog's.
- Operations live in `src/lib/mcp-state.ts`, one store per server run: an operation id is valid only in the app session that made it, is single use, belongs to one company (`sign_invoices` for another company fails), expires after 180 seconds with GİB's code and gives the session back to the queue then, takes three wrong codes before it ends, and only one is open at a time (a new request ends the last). One SMS a minute, as the app's Kodu tekrar gönder waits. While an operation waits, the app's own GİB calls wait too, as behind the SMS dialog; the app shows a toast with Vazgeç, which ends the operation. Switching MCP or the actions switch off ends it as well.
- Destructive tools are rate limited per server run (deletes ten a minute, company details five, closing the session three, sign attempts ten).
- Faturalardan içe aktar runs one scan at a time for the whole app (`importRuns`, `src/lib/import-run.ts`), shared with the dialog: `scan_gib_import` joins the app's run of the same company and period, answers `import-running` while another one scans, and goes on from where a stopped run stopped. The app's GİB session stays open 45 seconds after the queue empties (`SESSION_LINGER_MS`), so calls close together share one login; quitting, a changed login and Oturumu kapat log out at once. A read tool refused for an open GİB session (`session-locked`) closes it as `close_gib_session` does and runs once more, only while the switch is on; a write tool never runs again and answers that the agent should call `close_gib_session` (`SESSION_LOCKED`).
- Every company-scoped tool takes an optional `company`: a company id or its exact VKN / TCKN from `list_companies`. Without it the call acts on the company active in the app. Naming another company never switches the app: the call gets that company's own context (`forCompany` in `src/lib/mcp-tool-kit.ts`), with its GİB account on the shared queue (the queue logs out and in between accounts as it does for any account change), its records written through `updateEntity` in the store, and caches keyed by its GİB account. Every JSON result and error names the company (id, name, VKN) so the agent can confirm to the user. `list_companies` shows each company's name, VKN / TCKN and whether its GİB login is set up, never a credential.
- Visibility: the MCP page's Ajan etkinliği keeps the last 200 calls in localStorage `angaria-mcp-activity` on this Mac (tool, time, company, a short summary the tool writes, the result or the error, and the input), with Temizle. Summaries come from each tool's `summarize`, which sees only the parsed input and never repeats a code. The input (2026-10-12, Mert: the log should show what each call got) is the call's arguments as indented JSON under Girdi, folded: the value of any key named like a code, password, token or secret is masked as ••••••, at any depth (`src/lib/mcp-activity-input.ts`; the IBAN stays, it is printed on every PDF), and an input is cut at 4096 characters. Entries saved before carry no input and show as they did. A toast tells the user when an agent signed, deleted a draft, customer or service, changed the company details or closed the GİB session, with a link to the place.
- The server's instructions (Rust, `rpc.rs`) describe the signing flow and the `company` argument; tools/list descriptions say which tools need the switch.

## Consequences

- With the switch on, a process that can reach the server (the same macOS user, see 0009) can delete drafts and records and change the IBAN without the user; it still cannot sign without the SMS code, which only reaches the user's phone. The switch, the toasts and the activity log are the safeguards; the default stays off.
- A prompt-injected agent could ask the user for "the code" for drafts the user did not intend. `request_signing_sms` returns what will be signed so the agent can show it, the app's toast says how many drafts are waiting, and the web page tells users to check before giving the code.
- An agent waiting for the user's code holds the GİB session for up to three minutes; the app's screens wait meanwhile, as they do behind the SMS dialog.
- Acting on a non-active company logs that company in on the shared queue and out again, so a screen's next call for the active company logs in afresh.
- `packages/mcp-server` (the standalone stdio server) still has no signing tool; the signing inputs live in `@angaria/mcp-server/inputs` with the others.
