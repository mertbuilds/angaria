# 0012. MCP without the window: background mode, menu bar, settings in Rust

Accepted, 2026-10-10. Builds on `0009-built-in-mcp-server.md` and `0010-mcp-agent-actions.md`; their server, access checks, tools and switches stand. Since `0013-free-and-open-source.md` (2026-10-12) there is no license error.

## Context

Mert: "the mcp should be able to work without the app open. should be controlled from menu bar. that icon can be hidden too". Under 0009 the tools worked only while Angaria's window was open: closing it quit the app, and the bridge's cold start (`open -g`) brought the window up in front of the user. The tools run in the webview (0009), so "without the app open" still needs the webview loaded, only not shown.

The MCP settings lived in the webview's localStorage (`angaria-mcp`). Rust could not read them before the webview loaded, yet it must know whether MCP is on at launch (a cold start for an agent, with MCP off, must end at once) and when the window closes (hide or quit), and the bridge, a separate binary, must know it without launching anything.

## Decision

- Settings in Rust. `enabled`, `allowActions`, `port` and the new `showInMenuBar` (default on) live in `mcp.json` in the app data dir, under `settings`, next to the token and the running port (0600, 0009). Rust reads them at launch (`McpState`) and is their source: the webview reads them before its first render (`connectMenuBar`, `src/lib/menu-bar.ts`), sends every change through `mcp_set_settings`, and takes changes made in the menu bar back from the `mcp:settings` event. localStorage keeps a copy for the browser build and as the migration source: on the first launch after this change Rust has no settings yet, and the webview's copy goes to Rust. Moving the source to Rust, rather than mirroring a JS source, means one writer for the file the bridge reads and no window where the two disagree at launch.
- Background mode. The main window starts hidden (`visible: false`) and is shown in setup unless the app was started with `--background`. A background app runs with `ActivationPolicy::Accessory`: no Dock icon, not in the app switcher, the webview loaded and hidden, so the MCP tools run. Showing the window (menu bar, Dock or Finder or Spotlight through `RunEvent::Reopen`, which macOS sends to the running app instead of starting a second one) switches back to `Regular`. While the server runs, an `NSProcessInfo` activity keeps App Nap from slowing a windowless app (idle system sleep stays allowed).
- Closing. The window's close button and ⌘W ask Rust (`window_close_requested`, after the vault flush): with MCP on the window hides and the app goes to the background; with MCP off it closes and the app quits as before. ⌘Q and the menu's Çık always quit.
- Cold start. The bridge reads `settings.enabled` from `mcp.json`. Off: it answers "Angaria’da MCP kapalı. Angaria › MCP’den aç." and opens nothing. Unknown (never opened since this change) or on: it runs `open -g -j -a <its own .app> --args --background --for-mcp` (the bundle found from the bridge's own path), polls `mcp.json` for the port for up to 15 seconds and forwards, or stops early with the same error once the app's webview saved MCP as off. A background app quits again when it has nothing to do: opened `--for-mcp` with MCP off, or MCP off and the menu bar icon hidden (`stays_in_background`, `src-tauri/src/background.rs`). A locked license keeps the existing Turkish tool error, reworded to cover a license that was never activated.
- Menu bar. A monochrome template icon of the A (`icons/tray/tray-template.png`, drawn by `scripts/build-icons.py` from the master's geometry; macOS tints it for light and dark menu bars). Its menu: the status line (MCP açık, 127.0.0.1:port / kapalı / başlatılıyor / başlatılamadı), MCP and Ajanlar onaylayabilir ve silebilir as checkmarks, Son ajan işlemleri (the last five calls: tool, company, relative time, result; the webview sends them after each call, `tray_set_activity`) with Tümünü gör, Angaria’yı aç, Yeni fatura, Girişte başlat, Çık. It is rebuilt on every change and when the pointer reaches the icon, so the times stay current.
- Hiding the icon. Menü çubuğunda göster on the MCP page. Hidden, MCP keeps working; the hint says to open Angaria from Finder or Spotlight to change settings.
- Girişte başlat. `tauri-plugin-autostart` with a LaunchAgent that passes `--background`. `SMAppService.mainApp` is path independent but cannot pass arguments and needs macOS 13 (the app supports 11), so a login launch could not be told apart from the user's. The LaunchAgent names the executable's path, so every launch renews it while it is on, and a moved app is fixed by its next start.

## Consequences

- An agent can reach the tools whenever MCP is on, whether the window is open, closed or the app was quit; the user sees no window or Dock icon for it. With the icon hidden and MCP on, Angaria runs with nothing visible; the MCP page says so where the icon is hidden.
- Toasts need the window: while it is hidden the activity log still records every call, and the toasts are not seen. macOS notifications for signing and deleting while hidden are not part of this change.
- Faturalardan içe aktar's offer after a company's first GİB login is shown, and marked shown, only in a visible window: a first login an agent makes while the window is hidden offers it when the window shows.
- A background start costs a full webview launch (a few seconds) before the first answer; the bridge waits up to 15 seconds.
- The first launch after an update with MCP off and never opened: the bridge cannot know MCP is off, launches the app, and gets the answer from the webview a moment later.
- Launching the binary directly (not through LaunchServices) still starts a second instance; macOS's own single-instance handling covers the Dock, Finder, Spotlight and `open`.
