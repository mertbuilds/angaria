# Angaria

Tauri desktop app that replaces the GİB e-Arşiv portal UI for Turkish freelancers. Read `docs/relaunch.md` first: it holds the product, repo layout, design, and go-live decisions for the relaunch.

Architecture decisions and their reasons live in `docs/adr/` (tooling, Polar, hosting, downloads and updates, analytics, the GİB emulator, secrets storage, form inputs, the built-in MCP server and what its agents may do); add an ADR when one changes.

## Layout

```
apps/
  desktop/      Tauri 2 + React 19 + Vite. Frontend in src/, Rust in src-tauri/ (with mcp-bridge/, the angaria-mcp stdio bridge).
  web/          angaria.app landing page. TanStack Start on Cloudflare Workers, Paraglide (tr only).
packages/
  earsiv-sdk/   GİB e-Arşiv portal client. tsdown build to dist/.
  gib-emulator/ Local GİB e-Arşiv portal and TCMB rates emulator. node:http, tsdown, vitest.
  mcp-server/   Standalone MCP server (stdio) with GİB invoice tools over the SDK; `./inputs` shares tool inputs with the app. tsdown, vitest.
  ui/           @angaria/ui design system: StyleX + Base UI components, theme, fonts. Source-consumed, no build.
  utils/        Shared helpers (TCMB rates). tsdown build, vitest tests.
```

## Commands

| Command          | What                                                                            |
| ---------------- | ------------------------------------------------------------------------------- |
| `pnpm dev`       | mprocs: desktop, gib emulator, web (`https://angaria.localhost`)                |
| `pnpm emulate`   | GİB and TCMB emulator on `http://127.0.0.1:5180`, restarts on code changes      |
| `pnpm build`     | turbo build (workspace packages first, then the desktop and web apps)           |
| `pnpm typecheck` | `tsc --noEmit` per package via turbo                                            |
| `pnpm lint`      | builds packages and web, then oxlint type-aware + TS errors (tsgolint)          |
| `pnpm format`    | oxfmt (write mode); `pnpm format:check` to verify                               |
| `pnpm test`      | vitest per package via turbo                                                    |
| `pnpm icons`     | rebuild every app and site icon from `src-tauri/icons/source/` (needs uv)       |
| `pnpm fonts`     | fetch Suisse Intl woff2 from R2 into packages/ui/fonts and derive the PDF's ttf |
| `cargo check`    | Rust check, run in `apps/desktop/src-tauri` (needs the MCP bridge built first)  |

Desktop: `pnpm --filter desktop tauri dev --config src-tauri/tauri.dev.conf.json` (same as `pnpm dev`; the overlay lets the app reach the emulator and gives it the green dev icon, `src-tauri/icons/dev` and `src/assets/app-icon-dev.png` from `pnpm icons`), `pnpm --filter desktop tauri build` for a bundle. Both build the MCP bridge first; before a bare `cargo check`, `clippy` or `test` run `pnpm --filter desktop mcp-bridge` once. `pnpm --filter desktop test:mcp` runs the MCP end-to-end test (Rust harness, bridge, emulator). The `.dmg` install window (dot grid and arrow, no text) is `apps/desktop/src-tauri/dmg`: edit `background.html`, run `render-background.sh`, commit the PNGs; the icon positions live in `bundle.macOS.dmg`.

Web: `pnpm --filter web dev`, `build`, `test`, `brand` (re-renders the OG image `public/og.png` with Suisse Intl; the favicons and other icons come from `pnpm icons`), `run deploy` (build + `wrangler deploy`; not before go-live, and `pnpm deploy` without `run` is pnpm's own command).

## Tooling

- pnpm workspaces + Turborepo, Node 24 (`.nvmrc`), pnpm pinned in `packageManager`. Shared versions live in the pnpm catalog (`pnpm-workspace.yaml`); packages use `catalog:`.
- Lint: oxlint with `@nkzw/oxlint-config`, type-aware (`oxlint.config.ts`). Format: oxfmt, single quotes, sorted imports (`oxfmt.config.ts`).
- Git hooks: lefthook. pre-commit runs oxlint `--fix` and oxfmt on staged files, then `pnpm lint`; commit-msg runs commitlint (conventional commits); pre-push runs typecheck and test.
- Workspace packages are consumed from their built `dist/`. Turbo's `^build` builds them before any dependent build, typecheck, or test, and Tauri's `beforeDevCommand` and `beforeBuildCommand` (`apps/desktop/src-tauri/tauri.conf.json`) go through turbo, so the app never bundles a stale SDK.
- The desktop dev server stays on the fixed port 5173 because Tauri loads `devUrl`. Web apps run behind portless (`https://<name>.localhost`) from `mprocs.yaml`.
- Never edit generated output: `dist/`, `apps/desktop/src-tauri/gen/`, `apps/desktop/src-tauri/target/`.

## GİB emulator (`packages/gib-emulator`)

- Never test against live GİB during development: the production portal issues real documents. The app has no GİB test portal mode (its shared demo accounts are locked by other people's sessions); the emulator replaces it. Use the emulator: `pnpm emulate`, users `33333301`/`1`, `12345678`/`angaria` and `87654321`/`angaria` (over two years of signed invoices, drafts and a cancelled one, for Faturalardan içe aktar), SMS code `123456`. README: `packages/gib-emulator/README.md`.
- SDK: `createClient({ baseUrl })`; TCMB: `fetchTCMBRates(date, { baseUrl })`. The SDK's tests start it in-process (`packages/earsiv-sdk/tests/emulator-setup.ts`); the smoke script runs against it unless `EARSIV_MODE=prod`.
- Desktop: Ayarlar › Gelişmiş › Emülatör (dev only) sends GİB and TCMB calls to `VITE_GIB_EMULATOR_URL` (`.env.development`, plain http: the Tauri http plugin does not trust portless's CA). `src-tauri/tauri.dev.conf.json` adds it, and the Polar sandbox of `.env.development`, to the allowlists for `tauri dev` only; production builds contain neither the URL nor the switch, and reach only production Polar. A plain browser reaches it too (browser fetch; the emulator allows CORS).
- Faults (latency, 5xx, HTTP 200 with an error text, maintenance HTML, session locks) and state: the `/__emulator` API.

## Desktop shell (`apps/desktop`)

- Routing: TanStack Router file routes in `src/routes` (`/faturalar`, `/faturalar/$ettn`, `/yeni?kaynak=&musteri=`, `/musteriler`, `/hizmetler`, `/mcp`, `/ayarlar`; the old `/musteriler?sekme=hizmetler` redirects to `/hizmetler`). The Vite plugin regenerates `src/routeTree.gen.ts` on dev and build; it is committed so typecheck and lint run without a build. Never edit it. `autoCodeSplitting` loads each route's component in its own chunk.
- Screens live in `src/pages` and routes in `src/routes`: a route file owns its URL (params, search) and renders its screen from `src/pages`.
- The frame lives in `src/shell`: `Screen` (a route's toolbar and content), `ListDetail` (list column and detail pane), `SearchableList` (a list column with search and ↑/↓/↵ keys), `useRequireCredentials`, `useAppActions`, the ⌘K palette and the shortcuts (⌘N, ⌘1-6, ⌘,). The sidebar shows the company switcher only with two or more companies.
- GİB: run every portal call through `gib` in `src/lib/gib.ts` (`gib.run`, `gib.lease` for SMS signing). SMS signing is one hook, `useSMSSign` (`src/pages/use-sms-sign.tsx`): Faturalar' SMS ile onayla and Yeni fatura's Oluştur ve onayla (create the draft, then sign it on the same leased session). GİB refuses a second login while a session is open, so the queue runs calls one at a time on one shared session; the query options there (`invoiceListQuery`, `invoiceDetailQuery`, `invoiceHTMLQuery`) already do. The SDK's `getDrafts` splits ranges into the seven days GİB allows per request.
- Errors: the SDK throws `GibError` (`code`: auth, session-locked, maintenance, network, ...; `gibMessage`: GİB's own text) for every portal failure, network and non-JSON replies included. The app shows errors only through `src/lib/gib-errors.ts`: `GIB_ERROR_COPY` (Turkish text and action per code), `describeError`, `toastError` (Ayarlar’a git when Ayarlar fixes it) and `ErrorState` (`src/shell/error-state.tsx`) for inline failures. Never put `error.message` on screen: GİB's text shows only as secondary detail, only when it adds information, never in English.
- Forms: TanStack Form through `useAppForm` (`src/lib/form.tsx`, web-starter's canon) and the bound fields in `src/lib/fields/` (text, number, date, choice, masked) on `FieldFrame` and `useFieldError` (`src/lib/form-field.tsx`). Checks live in a form-level `validators.onChange` (it also runs on submit), never a form-level onBlur and never on a field. A choice shows its error once changed; typed text once changed and left, or after a submit, then follows each keystroke. An error is text with an icon, tied to its control by `aria-describedby` and announced politely (`FieldError`, never `role="alert"`); a submit focuses the first invalid control. Rules that never block (`invoiceWarnings`) show as `FieldWarning`. A message that cites a rule links its official text from the citing words themselves ("VUK 231/5", not a separate Kaynak link): only rules verified against that text, from the registry `src/lib/rule-sources.ts` (URL, label, `verifiedAt`); the opener's scope allows exactly those hosts. Define such a message with `ruleMessage(...)` and `cite(rule, words)` there (its `.text` is the plain string validators, warnings and MCP carry), render it with `RuleText` (`src/lib/rule-text.tsx`, the kit's `SourceLink`: the message's color, a dashed underline), and add a validator or warning message to `RULE_MESSAGES` there so `FieldFrame` and the summary link it through `MessageText`. Inputs follow `docs/adr/0008-form-input-libraries.md`: React Aria for dates, Maskito only for fixed-shape IDs, `NumberInput` for amounts (`parseDecimal`, `formatAmount`). Yeni fatura's rules and GİB payload are pure functions in `src/lib/invoice-form.ts`; regulated values (KDV presets, units, supported invoice types, İstisna reasons, due-day presets, the 7-day window) in `src/lib/regulated.ts`; VKN/TCKN, IBAN, SWIFT, e-mail checks and the IBAN, phone and GTİP masks in `src/lib/tr-validators.ts`; the Turkish date parser ("dün", "15.10", "geçen ay sonu") and GİB date conversion in `src/lib/tr-date.ts`. The invoice form lives in the store and the mounted form writes every change back; the store bumps `invoiceFormRevision` when the form is replaced (reset, GİB invoice, customer, undo), and `/yeni` remounts the form on it. Until a form is started, `/yeni` offers the newest invoices to repeat (`src/pages/invoice-start.tsx`) and Boş fatura.
- TCMB rate: Yeni fatura and MCP always take TCMB's döviz alış from the previous business day's bulletin, the one the invoice day's Resmî Gazete carries (KDV Genel Uygulama Tebliği III/A-1.1), never by the time of day. There is no setting (the Kur günü choice was removed 2026-10-10; `main.tsx` deletes its old localStorage key `angaria-rate-day`). The field stays empty while that day's rate is loading or missing, so another day's rate never goes to GİB.
- Customers and services learn from every created draft (`learnCustomer` in `src/lib/customer.ts`, `upsertSavedItems`). A customer's invoice defaults (currency, invoice type, VAT rate, PDF language, due days) apply when it is picked (`applyCustomer`); without saved ones they follow where the customer is. A service keeps one currency with its price (`src/lib/services.ts`). A draft adds a new one in its currency and updates a saved one only from a row in that service's currency; one without a currency takes the draft's. A row converted from another currency (the row's `pickedFrom` says so; a typed row named like a service counts in the invoice's currency) leaves the service as it is, even with the price typed over. One saved before services had a currency takes the one every invoiced customer agrees on at load, else has none and counts in the invoice's currency until edited. Picked on Yeni fatura in another currency, its price is converted through lira (TCMB's rate for the service's currency, the invoice's own rate for the invoice's) and the price field says so; without a rate the price stays empty and says why, never converted silently. Son ödeme tarihi is PDF only (GİB has no such field), kept per ETTN in localStorage `fatura-due-dates` (`src/lib/invoice-due-dates.ts`).
- Faturalardan içe aktar (`src/pages/import-from-gib.tsx`, rules in `src/lib/gib-import.ts`): saves customers and services from the company's Onaylı invoices of the last 3 ay, 6 ay, 1 yıl or 2 yıl (drafts, cancelled and deleted ones are skipped). It lists GİB a week at a time, then reads each invoice's detail, as background tasks on the `gib` queue, two handed over at a time with a short pause, so the session stays open and the user's own calls go first; a call whose session expired goes again once. Customers are one per VKN / TCKN (on GİB's placeholders, per name and country) and learn their defaults from their newest invoice through `invoiceDefaults` and `learnCustomer`; services are one per name, unit and currency at the newest price. A saved customer or service (same name) shows as Zaten kayıtlı and is never changed. `ImportFromGIBProvider` (`src/shell/import-from-gib.tsx`) offers it once per company with Atla right after the first login GİB accepts (`onGIBLogin`, `importOffered` on the company), never on Yeni fatura or over another dialog; Ayarlar › Veriler and ⌘K open it again.
- Browser without Tauri: `VITE_GIB_FIXTURES=1` (dev only) answers GİB calls from `src/dev/gib-fixtures.ts`; with `VITE_LICENSE_BYPASS=1` the screens run in a plain browser. GİB credentials still need a username and a password in localStorage `fatura-entities` there (the vault is Tauri only).
- Styles: StyleX only, no Tailwind. `src/app.css` holds the few global rules (the element reset the screens are laid out against; html, body and #root never scroll or overscroll, only the shell's own regions do); anything else is a StyleX style next to its component.
- Invoice detail (`src/pages/invoice-detail.tsx`): one status word everywhere (filter, badges, header, MCP tools) from `invoiceStatus` (`src/lib/invoices.ts`): Taslak, Onaylı, İptal edildi (signed, then cancelled: GİB keeps Onaylandı and sets `iptalItiraz` 0, `iptalItirazDurumu` 1; 0 is İptal aşamasında), Silindi (a deleted draft; GİB shows no page for it). GİB's page shows in `InvoicePaper` (`src/pages/invoice-viewer.tsx`, math in `src/lib/invoice-zoom.ts`): fit to width (⌘0 and Genişliğe sığdır also scroll back to the top-left), ⌘+ / ⌘-, pinch (Ctrl wheel, WebKit gesture events); a click, Tam ekran or Space opens `InvoiceViewer` full screen, Esc closes. Its iframe is `sandbox="allow-same-origin"` so the app can read the page's height: the HTML has no scripts (`withQRCode`), never add `allow-scripts`. İndir offers the Angaria PDF and GİB's own document: the e-Arşiv PDF (the same page drawn by an off-screen WKWebView, `html_to_pdf` in `src-tauri/src/pdf.rs`, A4 wide, one page however long; `cargo run --example html_pdf -- page.html out.pdf` renders a file the same way) and GİB's zip (`downloadInvoice`, GET /earsiv-services/download). Every download (there, in the full-screen viewer, Yeni fatura's PDF) is written into ~/Downloads by `save_download` (`src-tauri/src/downloads.rs`; "name (2).pdf" when the name is taken, never an overwrite), and its toast (`toastDownloaded`, `src/lib/download-toast.tsx`) offers Finder’da göster and Aç (`@tauri-apps/plugin-opener`, open_path scoped to `$DOWNLOAD/*`).
- Theme: the app follows the system. Ayarlar › Görünüm saves a choice in localStorage `angaria-theme` (`src/lib/theme.ts`); `main.tsx` re-applies it before render. The GİB preview stays on white paper in both themes (dimmed a little in dark mode).
- Palette: `src/palettes.css` layers a color palette over the kit's theme by `data-palette` on `<html>`: mist (Serin, the default) or paper (Sıcak). `index.html` sets the default, `DEFAULT_PALETTE` in `src/lib/palette.ts` (a test keeps them equal, each palette's light and dark blocks in sync, and the CSS to exactly `paletteChoices`). Ayarlar › Görünüm › Renk paleti and ⌘K (Renk paletini değiştir) switch it and save it in localStorage `angaria-palette`; `main.tsx` re-applies it before render, and `usePalette` keeps both in step. Regions part by tone, not borders: StyleX reads the palette's own variables (card, divider, selection, nav row, paper, panel shadow) through `tones` in `src/shell/palette.stylex.ts`. The content floats as a rounded panel on the sidebar's tone (`panelInset`, `panelRadius` in `src/shell/shell.stylex.ts`); a rounded element in its corner takes the panel's radius minus its inset.
- Titlebar: macOS's overlay titlebar (`titleBarStyle: Overlay`, default traffic light position; the window is at least 720x480). Nothing textual or interactive goes in the top-left `shell.trafficLightsInset` x `shell.toolbarHeight` (80x52, `src/shell/shell.stylex.ts`) under the traffic lights: the sidebar header pads by the toolbar height, and a layer over the whole window (the full-screen invoice viewer) gives its bar the toolbar's height, starts it after the inset and marks it and its title `data-tauri-drag-region` (never its controls).
- PDF: `@react-pdf/renderer` is large, so `src/components/invoice-pdf.tsx` loads with a dynamic `import()` when a PDF is made. Keep it out of static imports (a type-only import is fine). The PDF prints a GİB country by its full name (`formatPDFCountry`: `label` and `en` in `GIB_COUNTRIES`); the GİB payload sends GİB's `value`, cut at 20 characters.
- Fonts: `pnpm fonts` (`scripts/fetch-fonts.sh`) gets the Suisse Intl woff2 files from the private R2 bucket `FONT_BUCKET` (default `suisse-font`) with `wrangler r2 object get` (wrangler login locally, `CLOUDFLARE_API_TOKEN` in CI) and decompresses them to the TrueType files the PDF embeds (`wawoff2`). It never fails: without the files the UI and the PDF use Inter. `scripts/release-mac.sh` refuses to build without them.
- Secrets: one keychain item (service `com.vinena.angaria`, account `vault`) holds every secret as JSON, `{ v: 1, license?, gibPasswords: { [entityId]: password } }` (`src/lib/vault.ts`; Rust `vault_read`/`vault_write` in `src-tauri/src/secrets.rs`). The app reads it once per launch, on first need, through the one instance in `src/lib/app-vault.ts`, serves every read from memory, and writes only when the serialized content changes. A typed password is written 500 ms after the last keystroke, sooner on blur, on leaving Ayarlar and on window close (⌘Q inside those 500 ms loses it). The first launch moves the old items (`license`, `license-key`, `gib-password:<entityId>`; `secret_get`/`secret_delete` exist only for this) into the vault and deletes them only after the vault is written; plaintext passwords in localStorage move on any launch the same way. Dev builds keep the vault in `dev-vault.json` (mode 0600) in the app data dir, so rebuilt unsigned binaries never ask for keychain access; `ANGARIA_DEV_KEYCHAIN=1` opts a dev build into the keychain, release builds always use it, and the dev log names the store at startup. Keychain errors keep their macOS access hint (`src/lib/keychain-error.ts`).
- License: the record (key, activation, check times) lives in the vault. It is written on a new status, key, details, expiry or check time, and for the time seen alone at most once a day (`shouldSaveLicense`); in between, lastSeenAt moves forward in memory, so a clock set back is caught at once while the app runs. `LicenseProvider` checks with Polar at launch, every six hours and on focus, and recounts the offline grace period hourly (`src/lib/license-watch.ts`), so the app can lock mid-session. `StoreProvider` sits outside `LicenseGate`, so a lock keeps the invoice form.
- Updates: `useUpdateCheck` (`src/shell`, called in `App` outside the license gate, so a locked app still updates) checks once per launch outside dev and offers the update in a toast; Ayarlar › Hakkında checks on demand. Both go through `src/lib/updater.ts` (`@tauri-apps/plugin-updater`, then `relaunch` from `@tauri-apps/plugin-process`).
- MCP (`docs/adr/0009-built-in-mcp-server.md`, `docs/adr/0010-mcp-agent-actions.md`): Angaria › MCP switches a built-in server on (off by default, `angaria-mcp` in localStorage with the port and `allowActions`). Rust (`src-tauri/src/mcp`) serves Streamable HTTP on `127.0.0.1:41234` (next free port up to nine on) for both protocol eras (2026-07-28 `_meta` requests, `initialize` up to 2025-11-25); it refuses a non-loopback Host, any Origin and a missing or wrong bearer token. The token and port are in `mcp.json` (0600) in the app data dir. Tools run in the webview: `src/shell/mcp-host.tsx` (outside the license gate) answers `mcp:call` events with `runMcpTool` from `src/lib/mcp-tools.ts` on the `gib` queue, then `mcp_respond`. The tools cover every operation of the app (invoice tools in `mcp-tools.ts`, SMS signing in `mcp-tools-signing.ts`, records and settings in `mcp-tools-records.ts`, Faturalardan içe aktar in `mcp-tools-import.ts`, all built with `defineTool` from `mcp-tool-kit.ts`); `MCP_TOOL_COPY` in `src/lib/mcp.ts` names them in tools/list order and marks the gated ones. Signing (`request_signing_sms`, then `sign_invoices` with the code the user gives the agent), deleting, changing the company details and closing the GİB session work only while İzinler › Ajanlar onaylayabilir ve silebilir is on; otherwise they answer how to turn it on. Signing operations (`src/lib/mcp-state.ts`) hold the company's leased GİB session, are single use, bound to their company and expire after 180 seconds. Every company-scoped tool takes an optional `company` (id or VKN / TCKN) and runs on that company's login and records (`forCompany`, the store's `updateEntity`) without switching the app; results name the company. Ajan etkinliği keeps the last 200 calls in localStorage `angaria-mcp-activity` (no arguments, codes or secrets); signing, deleting and changes show a toast. A locked license is a Turkish tool error. Clients use the bundled stdio bridge `angaria-mcp` (`src-tauri/mcp-bridge`, `bundle.externalBin`, built by `scripts/build-mcp-bridge.sh` into `src-tauri/binaries/`): it reads `mcp.json`, so client configs hold no secret, and opens Angaria when nothing listens. Kurulum (`src/pages/mcp-install.tsx`) adds the bridge to the user-level config of 22 MCP clients through `mcp_agents`, `mcp_agents_add` and `mcp_agents_remove` (`src-tauri/src/mcp/agents`, a table ported from add-mcp: `docs/adr/0011-mcp-clients-from-add-mcp.md`, resync with `scripts/sync-add-mcp.md`): files edited in place, comments kept, one `<file>.angaria.bak`, a broken file left untouched; Claude Code goes through its `claude` CLI when found.
- Import `.stylex.ts` files (e.g. `shell.stylex.ts`) by relative path: the StyleX compiler does not resolve the `@/` alias and the build fails.

## UI (`packages/ui`)

- Components from `@angaria/ui`; CSS from `@angaria/ui/fonts.css`, `@angaria/ui/theme.css`, `@angaria/ui/base.css` (page shell), imported in that order; app tokens from `@angaria/ui/tokens.stylex` (`colors`, `spacing`, `font`, `radius`, `motion`); theme control from `@angaria/ui/theme` (`applyTheme`). Import `toast` from `@angaria/ui`, never from `sonner`. A toast's `action` is its main button, `cancel` a second action (both close the toast), `closeButton` adds a close button; with two actions the buttons go in a row under the text. Sonner's CSS is unlayered, so the kit's toast look lives in unlayered rules in `src/base.css`.
- The package ships TypeScript source; every consumer compiles it with `@stylexjs/unplugin` (`stylex.vite({ useCSSLayers: { before: ['base'] } })`, see `apps/desktop/vite.config.ts`). Components take StyleX styles in `style`, never inline CSS.
- A new package or `@base-ui/react` subpath imported here also goes into `uiDependencies` in `apps/web/vite.config.ts`, or the web dev server finds it on the first request and serves SSR 500s while it re-bundles.
- Theme: `data-theme` on `<html>` absent = follow the system, `light` or `dark` forces one; the attribute also themes any subtree.
- Anchored popups (DateField, Popover, Select, Combobox, Menu) keep the side and alignment they opened on until they close: their Positioner spreads `useHeldPlacement` (`src/lib/popup.ts`), and their Popup takes `popupMotion` (opacity and a 0.97 scale over 150ms when a pointer opens it; no motion when a key opens it, when it closes, or under reduced motion). A new anchored popup does the same. No animation on typing, arrow keys or a keyboard choice. The date popover also keeps one height: the calendar always has room for six weeks and the text line for two lines.
- Popup triggers are static. Base UI measures the trigger as its popup opens, so a trigger that moves on press opens the popup off by the press, and the popup jumps when the trigger springs back. Button's press scale skips any element with `aria-haspopup`, `aria-expanded`, `data-popup-open` or a `*-trigger` `data-slot`, so every kit trigger is covered however it is composed with `render`; `pressMotion={false}` turns the scale off for a Button that anchors a popup any other way. A main action with a menu of related ones is `SplitButton` (`src/ui/split-button.tsx`, Button's `variant` and `size`), never two Buttons side by side: one pill, square at the seam, a 1px divider. It presses as one piece: holding the main half (pointer or Space) scales the whole group (`:has(> [data-split-main]:active)`, no scale under reduced motion) while both halves keep `pressMotion` off, and pressing the chevron moves nothing. No trigger moves on hover either, and opening changes only color (a chevron may rotate), never a label's weight or width. `apps/desktop/tests/static-triggers.test.tsx` checks every kit trigger and SplitButton against the real CSS: desktop tests run StyleX with runtime injection (`vite.config.ts`, mode `test`).
- A menu item takes a one-key `shortcut` (`DropdownMenuItem`, `DropdownMenuRadioItem`): it shows as a `Kbd` at the row's end, and the open menu picks the item on that key before its typeahead (marks folded, so Ö also answers to O). Faturalar's period menu uses them, and T opens that menu outside a text field. A range of days is `RangeCalendar` (same month view as `Calendar`).
- Icons center on the cap height of the text beside them, not its line box (Suisse Intl's caps sit about 0.05em above the line box's middle). Kit components wrap their bare text with `capText`; a span of app text next to an icon takes `capStyles.text` (both from `@angaria/ui`, `src/lib/cap-text.tsx`); an input's value moves down by `fontMetrics.capOffset` (`src/lib/tokens.stylex.ts`). `Kbd` draws ↑ ↓ ← → ↵ ⌫ ⌘ ⇧ ⌥ ⌃ as icons.
- Optional theme variables (`optional` in `src/lib/tokens.stylex.ts`: field fill, chosen tab, tooltip, switch thumb, link color) are unset in theme.css and fall back to the shipped look; an app's palette sets them (the desktop's `palettes.css`).
- Gallery (dev only): `http://localhost:5173/ui-gallery.html` (or `/?ui-gallery`) while the desktop dev server runs. Every component, light and dark side by side.

## Web (`apps/web`)

- Config: public `VITE_` values in `apps/web/.env.development` (Polar sandbox checkout) and `.env.production` (go-live TODOs); local overrides in `.env.*.local`. The `deploy` script refuses to build without `VITE_CHECKOUT_URL_YEARLY` and `VITE_CHECKOUT_URL_MONTHLY` (one Polar checkout link per plan; the pricing section's Yıllık / Aylık switch picks one, every other checkout button is yearly).
- Every user-facing string is a Paraglide message in `messages/tr.json`. Generated `src/paraglide/` and `src/routeTree.gen.ts` come from the web build, which `pnpm lint` and `pnpm typecheck` run first.
- Analytics: PostHog EU through the `/ingest` proxy, cookieless (`persistence: 'memory'`), page views plus named CTA events only. Without `VITE_POSTHOG_KEY` nothing loads.
- The privacy section lists exactly the hosts the desktop app reaches (`src/components/app-hosts.tsx`); a test fails when the desktop http allowlist or updater endpoint changes without it.
- `/mcp` (linked from the header) explains the app's built-in MCP server. `src/lib/mcp.ts` names its tools, marks the ones behind the app's permission switch and has the Claude Code command the app copies; a test fails when the desktop's tool list, gates or command change without it. Every claim on the page follows `docs/adr/0009-built-in-mcp-server.md` and `docs/adr/0010-mcp-agent-actions.md`.
- Color: `src/brand.css` layers the site's blue, `#0098f2` (`--brand`, `--brand-ink`, `--brand-tint`), and `--primary`/`--ring` over the @angaria/ui theme for the web only; StyleX reads them through `src/lib/brand.stylex.ts`. White text on `--brand` fails AA: fills carry black text, and blue text uses `--brand-ink`.
- Screenshots: the exports in `public/screens` (`docs/screenshots.md` lists them) are wired through `src/lib/screens.ts`; `Screenshot` picks the light or dark one by color scheme and crops for cards. Motion respects reduced motion and pauses off screen (`src/lib/motion.ts`).
- Nasıl çalışır shows three looping scenes, not screenshots (`src/components/step-scenes.tsx`, shared parts in `scene.tsx`). `useLoop` (`src/lib/loop.ts`) plays a scene's timeline with the Web Animations API on its `data-part` elements while it is on screen and pauses it off screen. Each part's own style is the scene's last frame, which the server and reduced motion show. Move only transform and opacity, and never on an svg element (Chrome runs those on the main thread): wrap the svg in a span.
